# Agent Dashboard 구현 계획

Zellij를 실행 기반으로 사용해 기존 agent-dashboard의 조회와 조작 기능을 이관한다. 첫 릴리스는 훅 기반 상태 수집과 조회 화면을 완성하고, 다음 단계에서 조작과 보조 메뉴를 추가한다. 티켓 처리와 후속 지시 실행 엔진은 이번 범위에 포함하지 않는다.

작성일은 2026년 10월 7일이다. 첫 조회 버전을 구현하고 실제 Zellij에서 수집기 수명, 여러 세션, 이동과 재로딩을 검증했다. 구체적인 지원 범위와 검증 결과는 [실행 검증 기록](runtime-validation.md)에 남긴다.

## 기준과 목표

기능 기준은 `zellij-with-codeagent`의 `internal/agentdashboard`다. 해당 대시보드는 데몬에서 목록과 이벤트를 받고, 데몬의 Monitor는 화면 내용과 pane 제목을 YAML 규칙으로 판별한다. 새 프로젝트는 훅 이벤트를 우선 사용하고 기존 화면 탐지는 필요할 때 도구별 보완 수단으로 이관한다.

백그라운드 수집기는 화면 pane과 독립적으로 실행한다. 같은 세션에 여러 클라이언트가 연결되거나 대시보드를 여러 번 열어도 상태 갱신과 외부 조작을 중복 수행하지 않아야 한다. Zellij pipe는 대상 플러그인의 여러 인스턴스에 전달될 수 있으므로 이 조건을 먼저 검증한다. [Zellij pipe 문서](https://zellij.dev/documentation/plugin-pipes)

## 단계와 릴리스

| 단계 | 결과 | 상태 |
|---|---|---|
| 프로젝트 초기화 | 범위, 구조, 기능 이관표 작성 | 완료 |
| M0 | Zellij 실행 조건 검증과 Rust 빌드 골격 | 조회 경로의 수명·동시 저장·재로딩 검증 완료, 조작 검증은 M3 |
| M1 | 상태 코어, 이벤트 계약, 수집기, 첫 도구 어댑터 | 코어·공유 저장소·프로세스 발견·Claude 훅 구현 |
| M2 | 조회 대시보드와 세션 간 이동 | 기본 조회·검색·선택·이동 구현, 그룹·계층 표시 미완료 |
| M3 | 저장 가능한 설정과 에이전트 조작 | 예정 |
| M4 | 마지막 지시, 에디터, 최근 경로, worktree 메뉴 이관 | 예정 |

M0부터 M2까지 통과하면 첫 조회 릴리스로 사용한다. M3는 기본 조작 릴리스, M4는 대시보드 보조 기능 릴리스다. 티켓과 후속 지시 메뉴가 빠진 상태를 기존 대시보드 전체 기능 완료로 표현하지 않는다.

첫 구현에서 상태 소유권을 확정했다. 세션별 작성자 선출 대신 모든 유한한 호스트 명령이 같은 JSON 저장소를 잠금 아래 갱신한다. 수집기의 복제 수와 무관하게 스캔 주기를 공유한다. 화면 이동 외의 외부 조작은 아직 제공하지 않아 요청 중복 배제와 intent/result 저장은 M3에서 검증한다. 직접 WASI 파일 접근 대신 호스트 어댑터만 상태 파일을 연다.

## M0 Zellij 실행 조건 검증

첫 작업은 임시 Zellij 세션에서 실행 조건을 확인하는 작은 플러그인을 만드는 것이다. 실제 사용자 설정이나 기존 플러그인을 교체하지 않는다.

1. Rust workspace에 순수 코어와 WASI 플러그인 crate를 만든다. 플러그인은 `_start`를 내보내는 실행 파일로 빌드한다.
2. 로컬 Zellij `0.45.0`에 맞는 `zellij-tile` 버전을 확인하고 잠근다. `wasm32-wasip1` 도구 체인과 의존성 빌드를 확인한다.
3. 같은 바이너리를 `mode=collector`로 백그라운드 로드하고 `mode=dashboard`로 화면에 로드한다. pipe 목적지 설정이 서로 구분되는지 확인한다.
4. pipe 입력, 플러그인 간 응답, 타이머, 호스트 명령 결과 이벤트를 확인한다. 필요한 권한과 거절 시 동작을 기록한다.
5. 화면 pane 종료, detach, 모든 클라이언트 연결 종료, 재연결, reload 각각에서 수집기 생존과 이벤트 수신을 확인한다.
6. 두 클라이언트와 중복 플러그인을 띄워 같은 요청을 전달한다. 상태 저장과 조작을 맡는 인스턴스를 정하는 방식 및 중복 요청 배제를 검증한다.
7. WASI 파일 접근 범위와 세션 간 공유 경로를 확인한다. 직접 접근이 부족한 작업만 유한한 호스트 보조 명령으로 수행한다.

완료 조건은 빌드 산출물, 재현 가능한 임시 세션 실행 방법, 위 시나리오의 결과 기록이다. 단일 작성자와 중복 실행 방지가 해결되기 전에는 입력 전송이나 종료 기능을 붙이지 않는다. 백그라운드 인스턴스를 하나라고 가정하는 설계도 채택하지 않는다.

## M1 상태 수집과 코어

1. 에이전트 ID, 세션 실행 ID, pane ID, 에이전트 실행 세대, 상태, 정보 출처와 관찰 시각을 정의한다.
2. 훅 이벤트와 발견 결과를 받는 상태 전이 코어를 구현한다. 화면 선택이나 정렬과 상태 변경을 분리한다.
3. JSON 메시지 버전, 이벤트 ID, 도구별 순서 정보, 대상 세대 검증을 구현한다. 중복과 이전 실행의 이벤트를 버린다.
4. 도구별 이벤트 지원을 실제 설치 버전에서 확인한다. Claude를 첫 어댑터 후보로 검증하고, Codex도 별도 검증 후 연결한다. 같은 이벤트 이름이나 JSON 형식을 제공한다고 가정하지 않는다.
5. 어댑터는 훅의 원본 데이터를 공통 이벤트로 바꾸고 상태 기록과 pipe를 전달한다. 실패나 권한 대기로 에이전트 턴을 무기한 막지 않는다.
6. 실행 파일과 Zellij 환경 정보를 이용해 수동 실행한 에이전트를 발견한다. 훅 미설치 또는 상세 상태 미지원이면 `found`로 표시한다.
7. 잠금으로 직렬화한 공유 상태 스냅샷을 사용한다. 고정과 별칭 설정은 실행 ID에 연결하고 M3에서 편집 경로를 제공한다. 원자적 파일 교체, 스키마 버전, 손상 파일 보존, 종료와 재실행 시 정리를 구현한다.
8. 새 보고가 없는 상태와 세션 종료를 구분한다. 프로세스가 존재한다는 이유로 작업 진행을 확정하지 않는다.

완료 조건은 이벤트 중복·역순·세대 교체 테스트, 수동 실행 발견, 훅 이벤트를 통한 상태 전환, 훅 없이 재연결한 경우의 복원이다. collector 재로딩 후에는 기록과 실제 실행을 대조하고 확인 전 캐시를 현재 상태로 표시하지 않는다.

## M2 조회 대시보드

1. 빈 목록, 최초 수집 중, 권한 거절, 수집기 연결 오류를 구분해 표시한다.
2. 도구, 상태, 프로젝트, 세션과 pane 위치, 작업 요약, 경과 시간, 마지막 보고 시점을 표시한다.
3. 긴급도 정렬, 세션과 프로젝트 그룹, 부모와 자식 관계, 고정 영역을 표시한다. 부모 정보가 없는 수동 실행은 독립 행으로 표시한다.
4. 기존 숫자 선택, `j/k`, 방향키, `Tab`, `R`, `Enter` 동작을 이관한다. `/` 검색은 새 기능으로 추가한다.
5. 다른 세션의 스냅샷을 읽고 변경 통지 pipe를 사용한다. 통지가 유실되면 제한된 주기 읽기로 수렴시킨다.
6. 같은 세션 pane으로 이동과 다른 세션 pane으로 이동을 구현한다. 클라이언트별 선택을 유지하고 정렬 도중 이동 대상이 바뀌지 않게 한다.
7. 활동 기록과 화면 크기 변경을 구현한다. 한국어, 긴 경로, 넓은 문자, 줄바꿈, 터미널 제어 문자를 처리한다.

완료 조건은 두 세션의 에이전트를 한 화면에서 확인하고 이동할 수 있으며, 화면을 닫아도 수집이 지속되는 것이다. 예시 이벤트가 아닌 실제 에이전트 이벤트로 상태 전환을 확인한다. 터미널 폭 40, 80, 120과 높은 행 수에서 선택과 스크롤을 확인한다.

## M3 에이전트 조작과 설정 저장

1. 고정과 별칭을 저장하고 화면 및 collector 재로딩 후 유지한다.
2. 선택한 에이전트에 여러 줄 입력을 전송한다. 조작 직전에 세션 실행 ID와 pane 세대를 재검증한다.
3. 종료 요청을 구현한다. 기존 고정 에이전트 종료 제한을 유지하고, 실제 호스트 결과를 받은 뒤 화면을 갱신한다.
4. 실행 경로와 도구를 선택해 새 pane에서 에이전트를 시작한다. 실행 요청과 생성된 pane, 프로세스, 실행 세대를 연결한다.
5. 외부 조작 요청의 ID와 처리 결과를 저장한다. 중복 요청에 기존 결과를 반환하고 성공 여부가 불명확한 요청은 자동 재전송하지 않는다.
6. 프로세스 종료나 pane 교체 도중 실패한 요청을 표시한다. 오래된 요청이 새 에이전트로 전달되지 않게 한다.

완료 조건은 같은 요청을 여러 플러그인 인스턴스가 받아도 입력·종료·실행이 중복되지 않는 것이다. 실행 직후 reload와 결과 기록 전 중단을 검증한다. 상태 파일의 이관과 기본값을 테스트한다.

## M4 대시보드 보조 기능

1. 마지막 지시 요약과 `p` 전체 보기, 마지막 출력 미리보기를 이관한다. 훅과 플러그인 입력으로 확보한 지시를 보관하고 확인할 수 없는 입력은 추측해 채우지 않는다.
2. `I` 외부 에디터 편집을 지원한다. 에디터는 일반 Zellij pane에서 실행하고 종료 결과와 파일을 받아 입력창으로 복원한다.
3. 최근 프로젝트 경로와 도구 선택, 부모와 자식 worktree 생성 및 이동을 구현한다.
4. lazygit 실행, 자식 worktree 셸 명령 실행과 결과 표시, 부모 에이전트로 merge 지시 전송을 이관한다.
5. 도구가 제공하는 훅을 확인한 뒤 Cursor CLI, `agy`, Hermes 어댑터를 추가한다. Pi는 대상 도구 식별과 실행 방식 확인 후 별도 프로필로 추가한다.

완료 조건은 [기능 이관표](feature-map.md)의 M4 항목마다 기존 동작과 비교한 재현 결과가 있는 것이다. 도구별로 탐지·요약·입력 지원 범위를 구분해서 표시한다.

## 후속 범위

티켓 CRUD와 작업자 큐, 후속 지시 자동 전달, 음성 알림 큐, 기존 HTTP API, 기존 SQLite 데이터 전체 이관은 별도 계획으로 다룬다. 승인·거절 훅은 상태 수집 훅과 별개 기능으로 취급하고 도구별 응답 계약 검증 후 추가한다.

이번 프로젝트는 기존 저장소의 전체 runtime을 옮기지 않는다. 대시보드 조작에 필요한 pane 어댑터와 최소한의 상태 저장만 구현한다.

## 검증 원칙

코어 테스트는 이벤트 순서, 실행 세대, 복구, 조작 중복을 중심으로 작성한다. 화면은 상태별 렌더링과 선택 유지 동작을 확인하고, 백그라운드 수명과 세션 간 동작은 실제 Zellij 임시 세션에서 검증한다.

코드가 생긴 뒤 기본 검사는 `cargo fmt --all -- --check`, `cargo test --workspace`, 플러그인 crate의 `wasm32-wasip1` release 빌드다. 실제 설치 시 경로를 안정적으로 유지하고 산출물을 원자적으로 교체한다. 기존 사용자 세션 reload를 자동으로 수행하지 않는다.
